## 阻止签收的问题

**P1　积木实际执行与用户看到的 Lua 会走进相反分支。** Renderer 生成右侧 Lua。Main 加载固定的 `script-handle.lua`，`advance_flow` 在 Lua 内推进控制栈，TypeScript 求值器使用 JavaScript `number` 和自己的类型、错误规则。两条路径的区别能在不接设备时观察到。本次在 Windows 点击「复制 Lua」，核对剪贴板和预览逐字相同，并把同一文本送入独立的原生 Lua 5.4。普通对照 `15 + 7` 在两边均为 22。[实际载入入口](../../src/main/runtime/script-lua-handle.ts#L50) · [运行时算术](../../src/main/runtime/master-script-runner.ts#L155) · [源码生成](../../src/renderer/features/scripts/blocks.ts#L493)

| 同一张流程 | 桌面运行 | 执行生成的 Lua 5.4 文本 |
| --- | --- | --- |
| `value = 9007199254740991 + 2`，判断 `value > 9007199254740992` | 变量为 `9007199254740992`，打印 `NORMAL` | 条件为真，打印 `ALARM` |
| `value = 1 / 0`，判断 `value > 7` | 在赋值处报「除数不能为零」并停止 | 进入真分支，打印 `ALARM` |
| `false == 0` | 报「比较两侧的值类型不一致」 | 进入假分支，打印 `NORMAL` |
| 无设备操作，计数循环中直接跳出，然后打印 `finished` | 打印 `finished` | 需要 `modbus.loop_step` 和 `modbus.break_loop`。仅有标准库时在第 2 行报错 |

Lua 允许宿主注册设备和时钟 API。当前产品明确要求有限数值和写入前类型检查，这些约束需要在用户实际执行的代码里一致体现。优先让桌面运行和预览消费同一份可执行代码，在宿主边界保留确认缓存、受保护写入和异步协议。直接在循环体内跳出可使用 Lua 的 `break`，跨错误处理函数的跳出另有作用域要求。复验应比较最终值、控制分支、错误位置及拟发送的写值。[Lua 5.4 类型与数值](https://www.lua.org/manual/5.4/manual.html#2.1) · [Lua 宿主扩展](https://www.lua.org/manual/5.4/manual.html#1) · [Blockly 代码生成](https://docs.blockly.com/guides/create-custom-blocks/code-generation/overview/)

**P1　只改日志文字，就把已导入流程的定时通道从 T7 改成 T0。** 便携文件的 `TIMER` 填数字 `7` 和字符串 `"7"` 都能导入。Windows 目录版打开数字版本时，Main 首次实际触发两次 T7，画布及预览却显示 T0。只修改一个日志积木的文字并保存，再次运行的两条记录均来自 T0。字符串版本在同一套操作中始终为 T7。领域解析接受数字，而 Blockly 下拉项使用字符串，反序列化时丢弃了无法匹配的值。应在文件边界统一通道表示，校验与编辑器读取同一模型，覆盖启动、停止、查询以及接收回调的字段往返。[通道解析](../../src/domain/master-script.ts#L308) · [编辑器载入](../../src/renderer/features/scripts/block-controls.ts#L125) · [下拉选项](../../src/renderer/features/scripts/blocks.ts#L171)

**P1　保存失败，新修订仍可运行。** 在隔离目录成功保存修订 0，用 Windows 独占文件句柄占用该工作区，再改名保存。原子替换返回 `EPERM`，磁盘保留旧名称和修订 0；Main 快照却发布新名称和修订 1。按原修订重试得到「流程已在其他页面修改」，直接请求 `script.start(revision=1)` 成功。失败窗口内的运行行为和重启后可以恢复的版本不同。应在持久化成功后提交本次脚本编辑、删除及修订号，失败时保留可重试草稿，验证这三种结果的一致性。[脚本保存命令](../../src/main/runtime/manager.ts#L738) · [磁盘替换](../../src/main/services/workspace.ts#L145)

**P1　在途写尚未确认，调试器已进入下一次暂停。** 在 `on_start` 发起一笔异步写，让另一个 `on_run` 在 25 ms 到期。分别测试手动暂停和在写积木上单步，两次都在应答返回前停在 `on_run` 的日志积木，此时已结算 0 步。释放应答后，界面状态仍为「已暂停」，计数变成 1，日志追加写入成功。独立窗口的原有桌面断言也曾观察到暂停期间 37 步变成 38 步。修复时要区分停止派发新操作、在途协议结算及真正暂停，把单步完成关联到用户所选步骤。真实的设备应答应照常结算。[暂停与就绪任务](../../src/main/runtime/master-script-runner.ts#L891) · [异步步骤完成](../../src/main/runtime/master-script-runner.ts#L925)

## 固定参数的工程判断

- T0–T7、默认周期 100 ms、可配周期 10–120000 ms 和主回调看门狗 10–10000 ms（默认 1000 ms）是已定义的产品契约。`on_run` 有独立截止时间。每轮最多 64 个调度边界或约 3 ms、每 1000 条 Lua 指令检查钩子是宿主调度参数。[领域参数](../../src/domain/master-script.ts#L56) · [事件时钟](../../src/main/runtime/script-event-clock.ts) · [运行钩子](../../src/main/runtime/script-lua-handle.ts#L57)
- 200 个积木、1000 步展开预算、8 层控制嵌套属于产品容量策略。实测 8 层接受、9 层拒绝。352 个已结算步骤的流程只保留最近 250 条步骤和 64 条事件日志，符合说明。Lua 标准并未规定这些应用层数值。[编译边界](../../src/domain/master-script.ts#L447) · [有界日志](../../src/main/runtime/master-script-runner.ts#L788)
- 正常现场数据通过工作区的从站 ID、点位 ID、映射与共享连接调度解析。测试使用固定模拟器端口及虚拟串口来建立可重复的联调环境。生产路径中应优先改动的固定值是导致漏判的 10 ms 复查，以及与实际调度无关的循环上限分支。[设备绑定](../../src/main/runtime/manager.ts#L1037)
