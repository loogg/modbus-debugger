# Host 数据读取与采样缓冲

需求依据为 2026-11-12 本会话确认的数据通道改造，延续 `codex/canvas-and-detachable-tabs` 分支。目标版本 0.17.0。

## 范围与验收基线

- Main 的确认缓存接收成功采集结果时，向已启用的实例点位缓冲追加有效样本。样本包含毫秒时间、单调时间、序号和值，相同值的连续采集分别保留。超时和解码失败通过既有通信状态呈现。
- 趋势组和已保存的画布曲线自动建立缓冲引用。编辑中的曲线注册临时需求。同一实例点位共享容量和数据，独立设备使用各自缓冲。首次加入可配置容量，后续入口显示现有容量和引用，实例页也能查看与修改。
- Host 以独立周期批量获取最新值和曲线新增样本。前端共享缓存按核对时间复用，合并同时发生的读取，控制在途请求和返回批量。各 Host 独立发布显示快照，隐藏页停止绘制更新，后端采样继续。
- 缓冲有界覆盖，读取携带代次与序号，重试不重复追加，覆盖/重新绑定明确报告可用范围。历史窗口支持补齐，多 Host 读取互不消耗数据。
- 数值曲线使用各自真实时间，允许不同采集块，直接连接有效点。光标吸附所有可见信号最近时间，其余信号各取最近有效样本，逐条显示毫秒时间、序号和值。
- 趋势组、画布曲线及实例点位支持 Main 生成 CSV 文件，按稳定快照导出当前缓冲或指定时间范围，保留原始数值精度。趋势页的 Record 操作替换为缓冲导出。旧历史会话可继续查看，兼容记录命令改为消费确认样本。
- Main 继续负责通信调度。0.17.0 验证时 Block 周期下限为 20 ms，该轮验证确认事件不会因 UI 刷新合并而丢失，5 ms 用于可控注入的缓冲吞吐测试。后续低周期改造见本文 0.18.0 章节。

## 数据流

```text
设备确认 -> Block Cache -> 实例点位环形缓冲 -> Main 批量读取 / CSV 导出
                                ^                      |
工作区趋势、画布引用 + 临时需求 ---+                      v
                                             前端共享缓存
                                              /       \
                                        Host A         Host B
                                        独立刷新       独立刷新
```

## 0.18.0 高速轮询与连接重试配置

需求依据为 2026-11-13 本会话确认的调度修改。日常增量实现与定向验证已完成，沿用当前分支及既有隔离测试目录。

- 数据块周期允许 0–60000 ms 的整数。0 表示尽快采集，多个到期块公平轮转，正周期从本次选中该块时计算。
- 请求任务结束时唤醒调度，未来到期的块按截止时间唤醒，保留每连接单在途和手工写入、RMW、回读原子组。
- 连接新增读取重试间隔，允许 0–60000 ms，旧工作区缺省沿用 50 ms。连接新建、编辑及设置页均可修改并保存，在线状态遵守既有锁定规则。请求间隔保留在高级设置中，缺省 0 ms。
- 常规轮询的失败重试按到期时间重新参与调度，等待重试时其他到期块可以执行。同一块的重试与常规轮询保持单一待执行状态。扫描及手工原子任务沿用连接重试间隔。
- 移除 RTU 超时后的固定 20 ms 恢复等待，超时清理过期接收状态，保留无在途帧诊断和流式解析。发送侧按串口参数满足帧间静默，接收分帧继续依据长度、CRC 和可信边界。
- 覆盖 0/1/5 ms 周期、同时间到期的公平性、请求间隔、重试 0/自定义/旧配置缺省、超时后其他块执行、扫描停止、断开取消等待、配置更换和写入原子性。RTU 验证移除固定等待后的半包清理、迟到帧诊断和合法帧恢复。
- 验证采用相关 lint、typecheck、定向 Unit/UI/Integration、PyModbus TCP/RTU 模拟器互操作。Browser Review 检查连接两个入口、数据块周期入口、保存重开、错误值和 1440×960 / 1024×680 布局。

### 实现与验证结果

- 已实现 0/1/2/5/10 ms 等周期入口、请求完成与到期唤醒、公平轮询和连接级可配置重试间隔。常规轮询重试按截止时间重新调度，保留单在途和手工原子组。旧工作区缺少 retryDelayMs 时继续采用 50 ms，显式 0 正常保存与执行。
- RTU 固定 20 ms 恢复等待已移除。超时半包即时清理，空闲迟到帧保留诊断，发送侧静默按串口参数和最新收发活动检查。分帧继续采用既有长度、CRC 和可信边界逻辑。
- 分批完成 190 项定向 Unit/UI/Integration，覆盖 14 个相关文件。其中新增调度测试 17 项，连接表单测试 11 项，Manager Snapshot/delta 回归 19 项。覆盖低周期、公平性、重试次数与间隔、等待重叠、扫描取消、断开取消等待、配置切换和零周期压力下的 RMW/写入/回读原子性。
- 独立 PyModbus TCP 的 8 项互操作通过，覆盖八种功能码、最大数量、异常、损坏响应恢复、延迟、写入应答丢失后回读及 Enum/String。常规串口互操作的 7 项因本机串口枚举为空而跳过。
- 另使用 PyModbus 3.15.0，以回环 TCP 承载真实 RTU ADU 验证同一 ConnectionRuntime。配置 5 ms 与 0 ms 两个块、60 ms 超时及 30 ms 重试间隔，750 ms 内分别确认 66 与 115 次采集，合计 182 次事务，解析错误 0。注入一次超时后，下一块约 0.205 ms 开始，失败块约 33.204 ms 后重试。结果覆盖 RTU 协议帧与调度，串口驱动和实际线缆时序需要具备串口环境复核。
- Browser Review 使用 `out/test-temp/polling-review/backend` 和端口 50520 的独立 PyModbus。已实操新建连接与设置页的 0/75 ms 保存重开、非法值恢复、在线锁定、高级请求间隔，以及模板块设置、编辑块弹窗、临时读取保存数据块三个低周期入口。Main 保存文件已核对 retryDelayMs=0、块周期 1/80/5 ms。

- TypeScript、相关 ESLint、27 份文档的 214 个本地链接和 `git diff --check` 通过。隔离 Backend、Renderer 和模拟器已收尾，测试端口已释放。
