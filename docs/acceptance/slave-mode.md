# 从站功能开发与验收

日期：2026-10-21–22。当前阶段：0.12.1 Windows x64 本地正式验收已完成，正在提交推送与线上发布核验。前两阶段的已执行证据继续保留，发布结果见[版本记录](../archive/acceptance-v0.12.1.md)。

## 本次需求与调用参数

依据用户“目前只支持主站，加入从站功能，按新增功能模板开始闭环开发”，使用项目本地 `gui-development` 工作流，沿用已有项目修改模板的需求、依据、范围、测试与交付字段。Skill 位于用户维护且不纳入 Git 的 `.agents/skills/gui-development/`。

- 目标：同一应用可作为 Modbus RTU 从站或 TCP Server，让外部主站读写本机数据；已有主站继续可用，两种角色可在不同连接并存。
- 依据：[产品规范](../project-spec.md)、[架构](../architecture.md)、[协议](../protocol/01-application-protocol.md)、[工程约束](../../AGENTS.md)。界面复用现有连接、从站、模板和实时数据界面。
- 范围：连接角色、TCP 监听/串口打开、多 Unit ID、模板定义的四类数据区、本地设值与保存初始值、八种正式功能码、异常响应、RTU 广播写、不发起轮询、共享 Cache/趋势/Recorder/诊断、启停和错误恢复。
- 初始阶段交付：源码、更新后的操作说明和真实验证记录；版本与 lockfile 为 0.12.0。当时用户未要求正式发行，未生成四种发行包；后续发布授权见文末。
- 测试：独立 TCP 主站/PyModbus，隔离目录 `out/test-temp/`；RTU 使用正式 SerialTransport 的可控串口适配测试。可用虚拟串口时追加真实串口联调；无物理设备的硬件项保留为未验证。

## 能力与取舍

| 能力 | 本次行为与依据 |
| --- | --- |
| 主站与从站 | 每个连接选择角色，旧文件缺省为主站。TCP 从站绑定本机地址，默认 127.0.0.1；可明确改为 0.0.0.0 接受外部设备。RTU 从站打开所选串口。 |
| 数据定义 | 复用从站实例与模板；仅响应已启用 Unit 和已定义连续地址，不按演示地址裁剪。不支持的功能码返回 01、地址错误 02、数据错误 03。 |
| 数据与设值 | Main 的 Block Cache 是本机设备的实际内存，本地命令提交成功才发布确认值；四个数据区均可本地设值，外部主站只能写 Coil/Holding。批量写先完整验证再原子提交。 |
| 初始值与恢复 | 新内存为零；可显式保存当前值为工作区初始值。停止/重启监听保留进程内存，应用重启加载保存的初始值；配置地址/类型变化重置对应内存，避免旧值冒充新设备。 |
| 观察与记录 | 请求/响应记入现有诊断；实时、趋势、Recorder 复用缓存；从站模式不创建 Scheduler Poll。主站独有的扫描/临时读取入口在从站连接中不提供，并在 Main 拒绝错误调用。 |
| 扩展功能 | 沿用正式协议范围 FC01/02/03/04/05/06/15/16。自定义功能码、设备物理行为脚本未由本次需求或产品定义，不作为从站基础能力交付条件。 |

## 实现方案

```text
连接 / 从站 / 模板 UI --细粒度 Command--> RuntimeManager
                                           |
                     +---------------------+----------------------+
                     | role=master                                | role=slave
              ConnectionRuntime                            SlaveRuntime
              Scheduler -> Transport                 TCP Server / SerialTransport
                     |                                      |
                     |                                请求流式分帧 -> PDU 校验
                     |                                      |
                     +---------- Block Cache <------ 原子读写与响应
                                     |
                        Snapshot / delta / Trend / Recorder
```

新增纯 TypeScript 请求 PDU 解码与从站执行器；复用 ADU 编解码和诊断。每个 TCP 客户端有独立 Framer 和有界发送队列，停止时关闭全部客户端和监听器；RTU 依据请求长度、CRC、可信边界和有界等待分帧。配置重建继续使用既有关闭屏障。

## 发现并修正的问题

1. 活动串口读取关闭后，Windows 虚拟串口立即重开偶发 Access denied：增加 20 ms 句柄释放屏障。对照实验有活动读取时 0 ms 失败、5/20/50/100 ms 成功；正式集成和实际 UI 停止/立即启动复验通过。
2. TCP 截断候选超时会丢掉后续合法请求：改为保留可信 MBAP 边界。长输入分段处理，RTU 噪声溢出保留可能的帧尾。
3. 本地设值没有线协议回读，ValueCell 原 pending 会一直等待：Main 先发布确认 delta，本地结果直接结束 pending；主站写后回读语义保持。
4. 诊断原先固定认为请求 TX / 响应 RX：按角色投影报文，异常 FC 归于响应，广播只有 RX。
5. 最小窗口分页操作落到屏幕外、部分提示沿用主站“断开/轮询/寄存器”文案：调整内存滚动区高度并修正角色与位区文案，复验后收敛。
6. 初次保存启动值时新工作区路径没有随 delta 发布：保存后再发布 workspace delta，Main 回归明确断言生成路径到达 Renderer。
7. 本地 Enum 映射编辑必须执行和数值写入相同的有限值/范围校验，拒绝 Infinity、65536、负数等 UInt16 非法值，旧确认值保持；主站写结果回归同时通过。
